## 网页时序

`sudoku-demo-player.js/css` 在现有官方手机外框内叠加视频。手机可见且章节淡入完成后自动静音播放一次；切换标签会播放对应过程。结束后使用同一成片的终帧，不换回不同局面的旧图。

播放器通过 `sudoku:demo-state` 与 `sudoku-anatomy.js` 协作：

1. `playing`：保留最终版式占位，隐藏分析，暂停说明按钮的焦点与点击。
2. `complete`：终帧解码与布局稳定后，从控件框/端点开始，向外生长长水平折线，随后显露点阵轮廓、像素图标与说明。每组相差 230ms，主棋盘八组约 2.87s 完成。
3. `ready` / `failed`：减少动态或播放不可用时显示静态界面；减少动态直接显示完整分析。

2026-10-27 微调：逐段抽帧标记主界面转场落定的位置，在该位置触发一次 `analysing`：主棋盘 1.00s、辅导 2.10s、设置 1.00s、经典残局 2.80s、分步解法 1.30s、分享 2.00s。优先跟随实际视频帧回调，兼容回退到 `timeupdate`；录屏继续按原速播完，生长的持续时间与错峰间隔不变。分步解法的数字可在组件布局稳定后继续演示。仅在同一终帧已解码且布局就绪时触发，否则沿用结束后展开。结束交接不重启这次生长动画。抽帧证据保存在本地 `artifacts/sudoku-stable-cues-20261027/`。

保留一个「重看过程 / 直接看拆解」动作，用户可重播或跳过。离屏、页面隐藏、打开截图或共享视频弹窗时暂停，返回后继续；结束后不会循环播放。原有截图放大、键盘焦点恢复、语言切换与滚动吸附保留。

这类有自己播放与定格时序的叙事视频用 `data-video-detail-ignore` 避免被共享脚本包装成第二个播放器；仍使用硬件轮廓与站内素材保存限制。
