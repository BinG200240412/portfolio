# 作品集内容与视觉规范

全站原则：先让作品被看见、被体验，再用必要文字帮助理解。首页现有的简洁信息密度是参照。

1. **视觉承担主体。** 每屏先确定要展示的作品原图、视频、真实演示、对照或关系图；文字补充图像看不出的动机、设计取舍与事实。
2. **同一信息只说一次。** 标题已经说清的内容，不再用副标题、段落和图注反复解释。图片和版块不必强配说明文字。
3. **能展示就直接展示。** 操作由演示说明，变化用前后对照，关系用图示与必要标签；不把动作逐句翻译成长段文字。
4. **删掉没有信息增量的字。** 优先去除填版口号、泛化栏目导语、装饰性编号、无意义小标签，以及复述整页内容的结尾。没有素材时保留留白，不补空话。
5. **保留独有且必要的信息。** 项目名称、关键动机与取舍、真实角色与成果、素材来源、必要操作与状态需要清楚可读；alt、aria 和错误反馈不能当作冗字删除。完整技术细节与开发日志可按需展开，无意义内容直接删除。
6. **靠判断验收。** 不设机械的字数或图文占比，不靠缩小字号、降低对比度或把重复文字折叠起来制造简洁。检查删掉一句话是否会损失作品独有的信息，以及这条信息是否已由视觉表达。
7. **让层级递进。** 章节主标题大于子栏目标题，子栏目标题大于具体单元标题；正文退到单元标题之后，必要图注与来源只做辅助信息。借助字重、灰度和留白表达关系，不用同一大字号覆盖父子标题，也不让艳色小字抢视线。删除仅为分隔文字而画的横线；作品字标、图片原文和图表刻度依作品视觉保留。

适用于所有既有与新增页面。修改某一版面时，先清理该版面的重复信息，再决定需要补什么视觉素材；避免把每个版面都做成标题加长段落的同一种模板。

## 每件作品的基本信息

在原有封面文字区或紧接封面的项目介绍中，清楚交代项目是什么、**开始时间**、**负责事项**、**进度**。合作项目补必要的合作背景并保留团队署名；独立项目直接写清作者承担的设计与实现，不为统一形式凑合作栏。已有的角色与状态说明原位整理，不另加重复概览或求职入口。

开始年月采用 `YYYY.MM`（如 `2025.06`），首页项目经历和详情页共用 `assets/project-dates.js`。优先作者确认和原始项目记录，不把建站、文件日期或正式命名时间写成项目起点；未核实的年月暂不显示，也不使用“待补”占位。

各页复用信息项与 `assets/project-overview.css` 的阅读层级，不强制同一种版式。角色写具体工作，经历写真实取舍，进度分清已发布、可玩原型、概念方案和待验证部分。第一人称、简短、贴合项目，不能用“全流程赋能”等套话替代作者行动。AI、模型、库和团队成员的贡献与作者的判断分别说明；缺事实不编造。正文的经历与过程沿用下方个人成长线，不再复制一套感想。

## 过程中的动机与判断

动机、取舍和成长是叙事内容，不是每件作品都要填的两个栏目。不要统一列出“为什么做／从中学到”，不另设结尾反思卡，也不只换成更文艺的同义标题。

把起因放在项目缘起，把选择放在对应的原型、图像或方案对照旁，把方法变化与验证放在实际发生的板块。读者应从“遇到什么、怎样判断、做了什么调整、结果到哪一步”自然体会作者的思考与学习；不要求每件作品复用这几个小标题或同一种排版。现有内容已经说明的直接删除重复总结，没有必要为了证明成长添一段自我评价。

优先作者原话、真实版本和制作记录。区分实际完成、已验证的局部与概念设想；不能把此前代拟的反思当作已证实的个人经历，也不虚构问题、反馈或学习成效。缺事实在内部记录，不在公开页面用“待作者校准”的草稿说明填版。保持图像、演示和交互优先，中英文同步，融入后不增加泛化长文。

## 简历与介绍的排版

关于我的项目经历、教育背景、个人履历与荣誉属于同级信息。项目用可点击名称、开始年月和一句简短职责说明列出，不另做大标题卡片或两屏长介绍；详细动机、合作、过程和实现边界由各作品详情承载。

作品介绍随所在文字区的构图对齐。数独桌面端跟随右侧标题和操作区右对齐，手机转单列后随标题左对齐；左侧介绍和全宽章节从左侧起排。通过容器和响应式样式表达，不用脚本按文案长度猜测方向。
