# 首次打开与作品入口等待

基线 `10c7a1d`。保持原作品素材、点阵、字体、构图、中英文、黑白与返回层级。

## 已复现的原因

首页有 16 个阻塞渲染的样式请求，作品页有 7–26 个。联系页、聊天框等尚未使用的样式也位于首页关键路径。真实 Chrome 中只延迟 `contact.css` 4.5 秒，就使首页 FCP 从约 1.13 秒推迟到 5.66 秒；导航与点阵也一起推迟。

正文末尾的普通导航脚本会等待前面的样式，但不等待全部 defer 脚本。单独延迟后排 AI 脚本时，首页仍可见且可点击。不能把 DOMContentLoaded 时间直接当作首屏时间。

## 修改

- `build-page-styles.py` 将 14 个入口原有的 193 个样式引用生成到各自 HTML。CSS 原文件仍是编辑来源；级联次序、媒体条件和真实字体/图片地址保留。首屏无需再等待多个独立样式响应。
- `sync-shared-assets.py` 最后重建页面样式，再按内容更新作品 HTML 路由版本。生成器的 `--check` 检查内容是否过期，不引入每次变化的随机缓存参数。
- 作品请求 9 秒未就绪时展示原有简短错误和手动重试。重试创建新 iframe、释放旧生命周期；退出取消等待。旧请求的事件不能解除新请求的等待，迟到成功仍可恢复，BFCache 保留暂停/恢复。
- 媒体规范检查识别生成的内联样式；档案 PDF 下载与其他媒体只供预览的规则保持。

## 验证

- 浏览器受控对照：给非首屏 CSS 增加 3 秒延迟。桌面旧版 FCP/点阵首亮为 3164/3189 ms，新版 168/166 ms；手机旧版 3164/3180 ms，新版 132/151 ms。首页 CSS 请求 16→0。这是本地慢依赖场景，不能作为公网加载时间宣传。
- 1512、390、2560 像素，中英文、黑白、首页及直接 About/Contact 共 7 组，对照关键元素计算样式与几何一致，无页面溢出、JS 错误或资源失败。
- 13 个独立入口打开后有可见标题，无 JS 错误、横向溢出或资源错误；首页另作上述首屏验收。
- 真实浏览器故障场景验证超时、无自动重试、迟到成功、手动重试隔离、退出及 BFCache 的定时器清理。
- 全部 CSS 相对 URL 的解析目标与原版一致，`media` 顺序逐项一致；生成器重复运行无变化，媒体展示规范检查通过。

首页压缩后的 HTML 从约 14 KB 增至 37 KB，最大入口约 57 KB；代价是样式不再作为独立请求跨页面复用缓存，换取首次内容不被某份额外样式拖住。字体、图像和 JS 继续使用原有独立缓存。

当前网站托管在 GitHub Pages / Fastly 海外节点。本机网络路径未复现国内 HR 裸网环境；修复已证实的页面阻塞不等于已证明所有地区的网络链路稳定。
