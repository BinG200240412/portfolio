# 轻声识别修复与豆包 2.0 接入

2026-10-31：作者反馈真麦克风听不清、语音动画背板遮住页面。本次修复采音门槛与动画结构，并将正式识别从本机 SenseVoiceSmall int8 改为本人已开通的豆包流式语音识别 2.0。

## 采音和界面

- 旧版 `heard` 必须超过固定 RMS 0.012 才允许返回录音，导致 RMS 0.006 的有效轻声即使手动停止也被丢弃。新版手动停止检查实际 PCM，等待最后一批工作线程音频；自动检测根据最近环境底噪及持续能量变化，停顿容差 1.8 秒。
- 识别出有效语音后可做最多 6 倍的有界增益，并限制峰值；持续背景噪声不自动放大。服务端整体 RMS 门槛从 82 降到 8 个 PCM16 单位，只剔除接近数字静音的录音，避免整段停顿把有效轻声压到原门槛以下。
- 点阵从 `.pa-window` 内移到外侧，作为独立 SVG 透明浮在页面上；无背景、边框、阴影、滤镜或背板，事件穿透。输入卡高度不因录音增加，保持底部圆角输入框。
- 本地真实 WebAudio 测试以中文 TTS 的 15% 音量、0.8 秒及零开头静音分别验证自动结束、动态点阵、有效 WAV 和草稿填入；没有访问实体麦克风。常量底噪、手动停止最后音频批次、中断和取消也有回归检查。

## 部署和限制

- `/opt/portfolio-ai/venv` 只新增固定 `websockets==15.0.1`，语音凭据由独立 EnvironmentFile 加载；文字问答仍走原 DeepSeek Key 与限额。只 restart 本任务的 `portfolio-ai`，旧数独/Caddy 进程身份不变，本次无 Caddy 配置修改。
- 固定 TLS 目的地，禁用代理和重定向；消息、解压、数量和最终文本均有限额；异常不返回供应商原始正文或凭据。语音单并发，独立 SQLite 限额保留，不自动重试已进入供应商的请求。
- 常驻懒启动事件循环及单线程 DNS 执行器，避免 `asyncio.run` 清理线程池时被卡住的 DNS 拖住请求。正常交换 25 秒截止，HTTP 线程等待 25.2 秒后取消；首次循环初始化也有独立上限。
- 公网识别通过后，停止并禁用本任务原 `portfolio-speech` 本机模型服务；保留文件供回滚，不影响其他服务。
- 官方 2.0 小时版后付费为 1 元/小时，试用资格与有效期以账户控制台为准；本站没有充值、购买或开启自动续费。次数限额不是供应商金额预算，提醒也不是硬停用开关。

真实实体麦克风、系统选中的输入设备和现场噪声仍需现场试说；上述测试不证明所有设备均无问题。后续若继续听不到，应区分浏览器采音是否为零与模型转写错误，不能再只换模型而不检查输入。
