初步实现路径

工作流一与组件说明

上传图像与语义反推

输入在良渚遗址公园采集的实景或参考图，先用 ImageScale 统一尺寸，再由 WD14Tagger 反推图像语义；将场景语义与艺术风格触发词组合成提示词。

LoRA 模型

围绕“水乡泽国”训练场景特征：莫角山夯土台基、干栏式木构、芦苇湿地，以及青灰水体、葱郁植被和柔光。将这些形态、纹理与色调作为风格约束，减少通用模型对特定建筑结构的偏差。

双 ControlNet 串联

提示词条件 → Lineart → Tile → KSampler。两个 ControlNet 采用接力式串联：Lineart 先约束建筑轮廓，Tile 再保留局部信息进行重绘，让结构与细节共同约束采样。

三阶迭代采样与模型选择

以 Flat-2D Animerge V3.0 和场景 LoRA 为画风基础，经过两次采样、中间潜空间放大和第三次采样，逐步补充细节。图中保留了各阶段原始参数，可放大查看。

案例概念

面向空间电影与游戏前期制作，将二维概念图转化为空间预演的起点。在实景搭建或精细建模之前，先通过全景与三维场景判断空间感、光影氛围和构图，降低前期试错成本。

关键要点和意义

锁定画风

让扩展区域延续首图的笔触、色调与建筑语言。原展板比较了 IP-Adapter 思路，实际节点采用 Flux-Kontext 与 ReferenceLatent 传入参考条件。

消除接缝

左右边界要能闭合，避免在环绕观看时出现明显断裂；生成后检查边界和地平线的连续性。

2:1 全景几何

等距柱状全景用 2:1 的长宽比对应 360° 经度与 180° 纬度。若把方形图直接按完整全景映射，天顶和地面会发生变形。

实现过程与放大组件

风格化单图经 VAEEncode 与 ReferenceLatent 转成潜空间参考条件；Kontext dev 在“create a 360 hdr”的提示词引导下延展场景，再进入高清重绘。

调试模式

先跳过高清放大，快速检查莫角山台基、芦苇荡等构图与画风。底图确认后，再开启放大步骤。

生产模式

将确认过的全景底图进行高清重绘，供后续场景与引擎使用。当前节点图保留了预览、对比与高清结果三个位置。

工作流程说明

模型加载

加载 FLUX.1 UNet／Transformer、VAE，以及 CLIP-L 与 T5XXL 双文本编码器。

参考条件与提示词

把图像参考与场景描述传入生成条件，保留原图画风，同时指定全景叙事。

全景采样

在 2:1 比例的潜空间中采样、解码，先确认构图，再决定是否高清放大。

无缝扩展方案

原展板还记录了 Seamless Tile 的环绕处理方案，用于进一步约束左右边界。

专业解码方案

Circular VAE Decode 与 HDR VAE Decode 是展板中的后处理扩展方案，用于保留环绕特性与动态范围。

HDR 导出方案

展板记录了 sRGB → Linear 的色彩转换，以及 32 位 .hdr／.exr 的导出路径；本页展示的是图像预览结果。

场景理解与提示词反推

Janus-Pro 图像理解

读取全景图，描述建筑、植被、地形、光影和构图。原节点的指令是“帮我具体描述这幅图，加入光影信息，构图信息，不超过75词”。

提示词怎样进入三维生成

将图像中的草屋、岩石、稻田、远山与积云转成文字条件。全景负责视觉输入，文字补充语义，再一起交给 Marble。

为什么做

我想测试生成式图像能否成为空间设计的起点，而不只是一张漂亮的结果图。

从中学到

我学会把风格、全景几何和场景理解拆成可检查的步骤；每一步都有输入、输出和验证标准，问题才不会被下一步掩盖。
